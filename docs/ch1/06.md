# 06. 묻고 답받기

> **지난 장면** 05강에서 **Transmittal** TR-0921로 기초 도면 30장을 받아 **문서대장**을 고쳤다. 그런데 **IFC**로 발행된 철근 배근도와 매입물 도면이 같은 자리에서 부딪친다.

## 겹쳐 본 두 장

책상 위에 두 도면이 겹쳐 있다. 하나는 `GR1-RB-C-DWG-1204 Rev.1`(상부 철근 배근도), 다른 하나는 `GR1-RB-C-DWG-1310 Rev.0`(기초 매입물 배치도)이다. 기초 매트 한쪽 구역에 장비 기초용 앵커볼트 묶음이 있는데, 그 자리를 상부 철근이 일정한 간격으로 지나간다. 철근 사이 틈이 앵커볼트 묶음보다 좁다. 도면대로라면 둘 중 하나는 들어갈 수 없다.

현장에서 "철근을 조금 벌리면 되겠지"라고 판단할 수도 있다. 하지만 철근 간격은 구조 계산의 결과이고, 그 계산은 설계사가 책임진다. 시공사가 정할 일이 아니다. 신입 기사는 두 도면의 해당 부분을 잘라 붙인 스케치를 만들고, Aconex에서 새 질의서를 연다.

```text
RFI No.      RFI-C-0047
Discipline   Civil
To           설계사 (A/E)          cc: 발주처 사업단
Subject      RB Foundation — Top rebar conflicts with anchor bolt group
References   GR1-RB-C-DWG-1204 Rev.1 / GR1-RB-C-DWG-1310 Rev.0
Question     The anchor bolt group shown on DWG-1310 coincides with
             top rebar on DWG-1204. Clear space between bars is less
             than the anchor bolt group width. Please advise the
             rebar arrangement at this location.
Proposed     Shift two top bars each side and add trim bars (sketch attached)
Impact       Affects U1-RB-FDN-1030 (top rebar). Response needed by
             start of top rebar placement.
Attachment   SK-0047-01 (overlay sketch)
```

::: term 정보 요청서 | Request for Information | RFI | 알에프아이
설계도서가 불명확하거나 서로 맞지 않을 때 시공사가 설계사·발주처에 공식적으로 묻는 문서. 질문, 참조 도면, 시공사의 제안, 공정 영향을 적는다. 번호와 회신 기한이 기록되므로 나중에 질의와 답변의 근거가 된다.
EN: "RFI-C-0047 was raised for the conflict between top rebar and anchor bolts."
:::

질의서의 "Proposed" 칸에는 당사의 해결안을 적었다. 결정은 설계사가 하지만, 시공사가 현장 사정에 맞는 안을 함께 내면 답이 빨라진다. "Impact" 칸에는 공정 영향을 적었다. 언제까지 답이 와야 작업이 멈추지 않는지 남겨 두는 것이다. 답이 늦어 공기가 밀리면 이 기록이 **공기연장** 요구의 근거가 된다.

<details><summary>❓ 먼저 생각해 보기 — 설계사 현장 주재원이 사무실 옆방에 있는데, 왜 말로 물어보지 않고 RFI를 쓸까?</summary>

말로 받은 답은 기록이 남지 않는다. 나중에 그 부분에 문제가 생기면 "누가 그렇게 하라고 했는가"를 증명할 수 없고, 책임이 시공사에 돌아온다. 또 설계사와 시공사는 서로 계약이 없으므로(02강) 공식 경로로 받은 답이어야 발주처도 인정한다. 원전에서는 시공 결과가 설계 근거와 이어져 있어야 하므로 기록으로 남는 질의가 원칙이다.
</details>

## 답이 오다

나흘 뒤 Aconex에 회신이 온다. 설계사는 당사 제안과 비슷하게 해당 구역의 철근 배치를 조정하는 상세 스케치를 첨부했다. 회신 끝에 한 문장이 붙어 있다. "This response will be incorporated into DWG-1204 Rev.2 through a design change notice."

RFI 답변은 질문에 대한 설명이다. 도면 자체를 바꾸는 것은 따로 공식 절차를 밟는다. 이 현장에서는 그 문서를 DCN이라 부른다.

::: term 현장 설계변경 요청·통지 | Field Change Request / Design Change Notice | FCR, DCN | 설계변경
시공 중에 설계도서의 일부를 바꿀 때 쓰는 공식 문서. 현장이 변경을 요청하는 문서(FCR 등)와 설계사가 변경을 알리는 문서(DCN 등)로 나누기도 한다. 이름과 흐름은 프로젝트마다 달라서 FCN, DCR, FCR 등 여러 명칭이 쓰이므로 해당 프로젝트 절차서를 확인한다.
EN: "The RFI response will be formalized by DCN-C-0021 and incorporated into Rev.2."
:::

## 그리기 전에 그려서 보이다

설계사의 답을 받았다고 바로 철근을 가공하지는 않는다. 철근 협력사가 실제로 자르고 구부릴 철근 하나하나의 모양, 길이, 위치를 그린 도면을 먼저 만든다. 설계 도면이 "무엇이 필요한가"라면 이 도면은 "현장에서 어떻게 만들 것인가"다.

::: term 시공상세도 | Shop Drawing | - | 샵드로잉, 상세도
시공사나 협력사가 설계도서를 바탕으로 실제 제작·시공에 필요한 치수와 상세를 그린 도면. 설계사나 발주처의 검토를 거친 뒤에 제작을 시작한다. 시공상세도 검토를 받았다고 설계 책임이 시공사로 넘어가지는 않는다.
EN: "Rebar shop drawings shall reflect the response to RFI-C-0047."
:::

시공상세도는 Aconex의 제출물 흐름으로 설계사에 보낸다. 제출물에는 시공상세도 외에도 자재 성적서, 시공계획서, 용접 절차서 같은 것들이 있다.

::: term 제출물 | Submittal | - | 서브미털, 승인요청
시공사가 발주처·설계사의 검토나 승인을 받기 위해 내는 문서. 시공상세도, 자재 자료, 시공 절차서, 시험 성적서 등이 있다. 무엇을 언제 제출해야 하는지는 계약서와 시방서가 정하고, 보통 제출 목록과 일정으로 관리한다.
EN: "Submittal SUB-C-0035 (rebar shop drawings, Zone A) was returned Code 2."
:::

열흘 뒤 검토 결과가 돌아온다. 화면의 회신 코드는 "Code 2"다. 이 현장의 문서관리 절차서는 코드를 이렇게 정해 두었다.

| 코드 | 이 현장 절차서의 뜻 | 다음 행동 |
|---|---|---|
| Code 1 | 승인 (Approved) | 그대로 제작·시공 |
| Code 2 | 조건부 승인 (Approved with Comments) | 코멘트를 반영해 진행, 수정본 재제출 |
| Code 3 | 반려 (Revise and Resubmit) | 제작·시공 불가, 고쳐서 다시 제출 |
| Code 4 | 참고용 접수 (For Information) | 검토 대상 아님, 기록으로 보관 |

::: term 승인 코드 | Approval Code (Review Status Code) | - | 코드 1, 코드 2
제출물 검토 결과를 짧은 코드로 나타낸 것. 코드에 따라 시공사가 진행해도 되는지, 고쳐 다시 내야 하는지가 정해진다. 코드의 개수와 뜻은 프로젝트마다 다르므로 반드시 해당 절차서를 확인한다.
EN: "Code 3 — revise and resubmit; fabrication shall not proceed."
:::

코멘트는 한 줄이다. "추가 철근(Trim Bar)의 정착 길이를 상세에 표기할 것." 협력사는 이 내용을 반영해 가공을 시작하고, 수정본을 다시 제출한다.

## 실습

P5 — 미니 Aconex에 RFI-C-0047을 등록하고, 질의 → 회신 → DCN 발행 → 시공상세도 제출(Code 2) → 재제출의 상태 변화를 한 줄씩 기록한다. 각 단계에 참조 도면 번호와 개정을 함께 적는다. (practice/README.md)

## 다음 장면

질의는 하나가 아니다. RFI 목록이 늘어나는 사이 공정 담당은 다른 화면을 연다. 도면과 계약서가 정한 일을 날짜로 바꾸는 프로그램 P6다. 원자로건물 기초를 몇 개의 작업으로 쪼갤지 정하는 일부터 시작한다.

## 확인 문제

<details><summary>1. RFI-C-0047의 "Impact" 칸에 공정 영향을 적어 둔 이유는?</summary>

언제까지 답이 와야 작업이 멈추지 않는지 기록해 두기 위해서다. 회신이 늦어 공기가 밀리면 이 기록이 시공사 책임이 아닌 지연임을 보여 주는 근거, 곧 공기연장 요구의 근거가 된다.
</details>

<details><summary>2. 시공상세도가 Code 2로 돌아왔다. 협력사는 철근 가공을 시작해도 되는가?</summary>

이 현장 절차서에서는 된다. Code 2는 조건부 승인이므로 코멘트를 반영해 진행하고, 수정본을 다시 제출한다. Code 3이었다면 가공할 수 없다. 코드의 뜻은 프로젝트 절차서마다 다르므로 해당 절차서를 확인해야 한다.
</details>

<details><summary>3. RFI 답변만으로 도면이 바뀐 것으로 보면 안 되는 이유는?</summary>

RFI 답변은 질문에 대한 설명이고, 도면 변경은 DCN 같은 별도 공식 절차로 이루어진다. 변경이 반영된 새 개정이 발행되어야 문서대장의 유효 문서가 바뀐다. 그 전까지는 답변과 변경 문서를 함께 참조해 관리한다.
</details>

<details><summary>4. 지체상금과 공기연장(EOT)은 어떤 관계인가? (04강)</summary>

지체상금은 준공기한을 넘긴 날수에 따라 무는 금액이다. 공기연장이 인정되면 준공기한이 그만큼 뒤로 바뀌므로, 그 기간에 대해서는 지체상금이 생기지 않는다.
</details>

<details><summary>5. 시공사와 협력사, 발주처 사이의 계약 관계를 말하라. (02강)</summary>

발주처는 시공사와 계약하고, 시공사는 협력사와 계약한다. 협력사는 발주처와 직접 계약이 없으며, 협력사가 한 일에 대한 발주처 상대 책임은 시공사가 진다.
</details>
